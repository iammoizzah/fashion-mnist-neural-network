# Building, Breaking and Fixing a Neural Network

A complete neural-network study on the **Fashion-MNIST** dataset using **NumPy and PyTorch**.

This project explores not only how to build a neural network, but also how to understand its gradients, compare different training choices, deliberately make it overfit, apply regularisation techniques, and finally select a model using hyperparameter tuning with k-fold cross-validation.

---

##  Project Overview

The project follows a complete experimental workflow:

1. Environment Setup
2. Backpropagation From Scratch
3. Baseline Model and Activation Study
4. Loss Function Comparison
5. Optimizer Comparison
6. Deliberately Forcing Overfitting
7. Regularisation Study
8. Hyperparameter Tuning with 5-Fold Cross-Validation
9. Final Evaluation on the Held-Out Test Set

The main goal was to understand the relationship between:

- Model architecture
- Activation functions
- Loss functions
- Optimizers
- Overfitting
- Regularisation
- Training data size
- Hyperparameter tuning
- Generalisation performance

##  Dataset

The project uses the **Fashion-MNIST** dataset.

Fashion-MNIST contains grayscale images of clothing items belonging to 10 classes.

Each image:

- Has a resolution of **28 × 28 pixels**
- Contains **784 input features** after flattening
- Belongs to one of **10 classes**
- Has pixel values normalised to the range **[0, 1]**

# 🔬 Experiments

## Part 1 — Backpropagation From Scratch

A simple multilayer perceptron was implemented using **NumPy only**.

### Architecture

```text
784 → 64 → 10
```

The implementation included:

- Forward propagation
- ReLU activation
- Softmax
- Cross-entropy loss
- Manual gradient calculation
- Gradient descent

The manually calculated gradients were then compared with gradients generated by PyTorch.

The maximum absolute differences were approximately:

```text
W1: 2.05e-08
W2: 3.89e-08
b1: 9.83e-09
b2: 1.39e-08
```

These very small differences are consistent with floating-point precision, confirming that the manual backpropagation implementation was correct.

# Part 4 — Optimizer Comparison

Four optimizers were evaluated:

- SGD
- SGD + Momentum
- RMSProp
- Adam

The optimizers were tested with tuned learning rates.

| Optimizer | Learning Rate | Epochs to 85% | Final Validation Accuracy | Wall-Clock Time (s) |

It also reached the 85% validation-accuracy threshold in only 2 epochs.

Adam was therefore selected as the preferred general-purpose optimizer for the later experiments.

# Part 5 — Deliberately Forcing Overfitting

To demonstrate overfitting, a much larger network was trained using only **2,000 training samples**.

### Architecture

```text
784 → 512 → 512 → 512 → 512 → 10
```

The model was intentionally given high capacity relative to the amount of training data.

### Results

```text
Training Accuracy:    99.40%
Validation Accuracy:  82.92%
Generalisation Gap:   16.48 percentage points
```

The first epoch where training loss decreased while validation loss increased was:

```text
Epoch 6
```

The first epoch where training accuracy exceeded 99% was:

```text
Epoch 48
```

### Diagnosis

The model showed **high variance / overfitting** rather than high bias.

The model learned the training data extremely well but failed to generalise equally well to unseen validation data.

---

# Part 6 — Regularisation Study

Several approaches were tested to reduce overfitting:

- L2 weight decay
- L1 regularisation
- Dropout
- Batch normalisation
- Early stopping
- Data augmentation
- Increasing the amount of training data

## Results

| Method | Setting | Train Accuracy | Validation Accuracy | Gap |
|---|---|---:|---:|---:|
| Baseline | None | 99.40% | 82.92% | 16.48 |
| L2 | λ = 1e-05 | 100.00% | 83.01% | 16.99 |
| L2 | λ = 0.0001 | 99.95% | 82.50% | 17.45 |
| L2 | λ = 0.001 | 98.05% | 82.11% | 15.94 |
| L1 | λ = 1e-6 | 99.05% | 81.96% | 17.09 |
| Dropout | p = 0.1 | 99.30% | 82.76% | 16.54 |
| Dropout | p = 0.3 | 98.90% | 83.14% | 15.76 |
| Dropout | p = 0.5 | 96.40% | **83.72%** | **12.68** |
| Batch Normalisation | Enabled | 100.00% | 82.67% | 17.33 |
| Early Stopping | Patience = 5 | 85.05% | 80.24% | 4.81 |
| Data Augmentation | Flip + Rotation | 100.00% | 81.14% | 18.86 |
| More Data | 10,000 samples | 99.41% | 86.10% | 13.31 |
| More Data | 20,000 samples | 99.31% | 87.70% | 11.62 |

### Key Findings

Dropout with `p = 0.5` provided the best trade-off among the tested regularisation techniques.

It reduced the generalisation gap from:

```text
16.48 → 12.68 percentage points
```

while maintaining:

```text
96.40% training accuracy
```

Increasing the training set to 20,000 samples also produced a strong improvement, reducing the gap to:

```text
11.62 percentage points
```

while maintaining 99.31% training accuracy.

Early stopping produced the smallest gap overall, but it also resulted in a large reduction in training accuracy.


### Interpretation

The hyperparameter-tuned model **did not improve** the test accuracy over the Part 2 baseline.

This is an honest negative result. The original baseline was already strong, and the configurations selected through cross-validation did not provide better generalisation on the held-out test set.

The result also demonstrates an important machine-learning lesson:

> Hyperparameter tuning does not guarantee improved test performance.

A tuning procedure should therefore be evaluated objectively rather than assuming that the final model must outperform the baseline.

# 💡 Key Takeaways

### 1. Backpropagation can be implemented manually

The NumPy implementation produced gradients extremely close to PyTorch's gradients, validating the mathematical derivation.

### 2. Activation functions affect gradient behaviour

Sigmoid produced smaller gradients than ReLU in the experiment, while ReLU provided stronger gradient flow.

### 3. The loss function matters

Cross-Entropy outperformed MSE for the classification task.

### 4. Optimizers affect convergence

Adam and RMSProp reached high validation accuracy faster than standard SGD.

### 5. High training accuracy does not mean good generalisation

The deliberately overfit model reached 99.40% training accuracy but only 82.92% validation accuracy.

### 6. Regularisation can reduce overfitting

Dropout and increasing the amount of training data reduced the generalisation gap.

### 7. More data can be highly effective

Increasing the training set from 2,000 to 20,000 samples reduced the gap substantially while maintaining high training accuracy.

### 8. Hyperparameter tuning is not guaranteed to improve the final result

The tuned model achieved exactly the same test accuracy as the Part 2 baseline:

```text
89.30%
```

This provides an honest demonstration that model selection and tuning do not always produce measurable gains on a held-out test set.
